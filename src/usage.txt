# vysu — look at a real app the way a reviewer does. One agent-browser session per persona, logins
# kept across runs, screenshots and contact sheets outside every repo. Works on any web page: the
# persona only names the session; `-` is an anonymous one.
#
# What the app decides — origin, auth, language key, bundle id, services, personas, push payloads,
# brand — lives in `.vysu/config` at the root of that project, found by walking up from the cwd.
#
#   vysu <persona> <agent-browser args…>    passthrough (session <project>-<persona>, state restored)
#   vysu walk <persona> <name> --url <url> [shots options…]   open + check + shots + report, in one call
#   vysu login <persona> [url]              log the persona in through the project's auth connector
#   vysu up <service> [--env k=v]…          start a service declared in the config, wait for its health
#   vysu up all | down <service> | down all | down metro | down applog [ios|android]
#                                           down metro: this owner's isolated Metro (else the shared one, only
#                                           when this owner started it); down applog: the log tails, JS ones included
#   vysu up ios|android [--build] [--reinstall] [--avd <name>] [--device <name>]   the device, and what runs in
#                                           front of the app: Metro in expo mode, then the app started straight onto
#                                           it (left as it is when it already runs there), nothing in native mode
#                                           (VYSU_MOBILE_KIND) where `up` installs the app from VYSU_IOS_APP_PATH /
#                                           VYSU_ANDROID_APK and tails its log; --build runs VYSU_MOBILE_BUILD_IOS /
#                                           _ANDROID in the background; --device / --avd are remembered for this owner
#                                           iOS devices: the config's VYSU_IOS_DEVICE and VYSU_IOS_OLD_DEVICE
#                                           AVDs: the specs of VYSU_ANDROID_AVDS, created by `vysu setup`
#                                           VYSU_MOBILE_HEADLESS=1: no window — Simulator.app is not opened, the emulator
#                                           runs with -no-window; captures, taps, logs and mrec work the same
#   vysu up ios|android --isolated [--port <n>] [--dir <mobile dir>]   a Metro for this owner alone, from its own
#                                           checkout (default: the worktree the command runs in), on the next free
#                                           port from 8082; the device is relaunched onto it. ~1-1.5 GB of RAM:
#                                           `vysu down metro` hands the device back to the shared Metro
#                                           (VYSU_METRO_PORT, 8081) on its next relaunch
#   vysu ios|android <agent-device args…>   passthrough on the chosen simulator / emulator
#   vysu mlogin ios|android <persona> [--force]   log the persona in inside the app (one install = one
#                                           session); a device vysu recorded with that persona, whose app
#                                           shows someone signed in, is left as it is (--force: log in anyway).
#                                           A login takes one to three minutes: give the call a 5-minute timeout
#   vysu mshot ios|android <name> [label] [--baseline <name>] [--no-prev]
#              [--full [--step 150] [--max 12] [--top <pt>] [--bottom <pt>]]
#                                           screenshot (1x, steady status bar) into the shots folder; --full scrolls
#                                           and stitches, mobile has no full-page capture (--step: the scroll between
#                                           two captures, 150 pt by default — a flick asking for more lands no further;
#                                           --top / --bottom: the height of a bar drawn over the scroller, which
#                                           stitch cannot find on its own). Android captures the whole display,
#                                           system dialogs and keyboard included (the user's keyboard stands in for
#                                           agent-device's invisible input method during the capture). The same label
#                                           again: the earlier capture becomes <platform>-<label>.prev.png and one line
#                                           follows the path, « vs previous: unchanged » or the zones that moved and
#                                           the marked png (--no-prev: overwrite, compare nothing; --baseline: that
#                                           folder instead, printed as before)
#   vysu mtap ios|android "<label>" [--wait "<text>"] [--timeout <s>]   press by accessible label (then
#                                           visible text), settled; --wait: then that text, 10 s by default
#   vysu mdo ios|android [--shots <name>] [--keep-going] [--devices "<a>,<b>"] [--textsize "normal,xl"]
#            -- "<step>" … | <file|->       drive a screen in one call: per step one ✓ / ✗ line, then
#                                           « screen: <≤ 6 labels> (<n> nodes, +added −removed, keyboard) »;
#                                           stops on the first ✗ (exit 1) unless --keep-going. Steps (a
#                                           <text> is found in any label holding it, in any case):
#                                           tap "<label>" [--wait "<text>"] · wait "<text>" [<s>] · wait gone
#                                           "<text>" [<s>] · wait idle [<s>] · fill "<label>" "<value>" · type
#                                           "<text>" · key return|dismiss|back · scroll-to "<label>" [<max>] ·
#                                           expect [no] "<text>" · screen · shot <label> · open <route> · net
#                                           offline|online · perm <name> grant|deny|reset · relaunch · sleep ·
#                                           any agent-device verb. --devices × --textsize: the steps once per
#                                           pair, shots prefixed <device>-<size>-, one sheet, normal text after
#   vysu mwait ios|android "<text>" [--gone] [--timeout <s>] | --idle [--timeout <s>]   one line, exit 0 / 1
#   vysu mrelaunch ios|android [--textsize normal|large|xl] [--appearance light|dark] [--lang <l>]   kill + relaunch,
#                                           wait for the screen (dev menu and launcher cleared on the way, the
#                                           agent-device session reopened when it is gone)
#   vysu mreload ios|android                this device's JS only, reloaded in place (not every app on the Metro);
#                                           falls back to mrelaunch, saying why, when the device has no inspector
#                                           page of its own, or its app does not start the reload within 5 s or
#                                           fetch no bundle within 10 s of starting it
#   vysu mflow ios|android <file|-> [--shots <name>] [--keep-going]   the steps of a file, as `mdo` runs
#                                           them (tap t:<i18n.key> too) → ✓ / ✗ lines + contact sheet
#   vysu mrec ios|android <name> [--fps 60] [--crop x,y,w,h] [--strict] -- "<step>" …   record the screen while the steps run →
#                                           normalized H.264 clip + motion report + events.json (each step in clip
#                                           seconds, with the point it tapped)
#   vysu mlog [ios|android] [--device] [--errors] [mark | --tail N]   the app's log since this owner's last mark
#                                           (or its last N lines): Metro's in expo mode (logs/metro[-<port>].log),
#                                           logs/<platform>-app.log in native mode; --device: this device's JS console
#                                           only; --errors: errors, warnings and the first line of each stack, ×N for
#                                           repeats. Lines matching VYSU_MLOG_IGNORE are dropped (and counted). A
#                                           bundling failure since the mark comes first: « metro: bundle failed … »
#   vysu push ios <preset>                  simulated APNs on the iOS simulator (driver apns-sim)
#   vysu push <persona> <preset> [--platform ios|android] [--field k=v…]   a real push to the persona's devices
#   vysu textsize ios|android normal|large|xl   Dynamic Type / font scale of the running simulator or emulator
#   vysu appearance ios|android light|dark      system appearance of the running simulator or emulator
#   vysu mopen ios|android <route|url> [--wait "<text>"] [--timeout <s>]   a deep link, in the running app: a route
#                                           is appended to VYSU_MOBILE_DEEPLINK, a url goes as is; a cold app is launched
#                                           first (a raw cold link lands on the dev-client launcher), an « Open in … ? »
#                                           alert is pressed if iOS shows one; answers « opened <url> · screen: <labels> »
#                                           (--wait: a text only the target screen has, the surest and quickest check)
#   vysu mnet ios|android offline|online    airplane mode on the emulator, read back (`release --reset` turns it off);
#                                           iOS has no per-simulator network: exit 1, with what to do instead
#   vysu mperm ios|android <permission> grant|deny|reset   notifications · camera · photos · location · microphone ·
#                                           contacts · calendar, or the platform's own name; read back (dumpsys, TCC.db)
#                                           before it answers; reset = never asked, the app's next request prompts
#   vysu mburst ios|android <name> [--seconds 3] [--every 0.3] [-- "<step>" …]   screenshots as fast as the device
#                                           gives them while the step runs: the distinct ones at 1x, a one-row strip,
#                                           and one line of when each changed (a skeleton, a sheet, a toast)
#   vysu shots <persona> <name> [--url <url>] [--sizes WxH,…] [--dark] [--full] [--no-expand] [--no-warm]
#              [--lang <l>] [--freeze]
#                                           one capture per viewport, and the diff of each against:
#                                             --full                  the whole screen: unfolds the inner scrollers, for
#                                               an app whose shell never scrolls the document (--no-expand for a page
#                                               that does, and to see a sticky section where it sticks); the document is
#                                               walked through once first, so what a page reveals on scroll is painted
#                                               before the capture (--no-warm to skip)
#                                             --baseline <name>       an earlier shots folder
#                                             --baseline-url <url>    the same path elsewhere, captured now — a deployed
#                                               main is the baseline a branch is read against:
#                                               `--baseline-url https://main.example.com/<path>`, or `--baseline-url @`
#                                               for the same path on VYSU_BASELINE_ORIGIN (log the persona in there once)
#                                             --ignore <css selector> repeatable, those boxes are left out of the diff
#   vysu report <name> [--md]               a shots folder read back in ≤ 25 lines: what changed, what to open
#                                           (mobile: the device's text size, language, appearance and sha, then each
#                                           capture's last verdict, vs previous or vs a baseline)
#   vysu flow <persona> <file|-> [--shots <name>] [--viewport WxH]   scripted web steps (go · click · fill · press ·
#                                           shot [--full] · check)
#   vysu rec <persona> <name> [--fps 30] [--viewport 1440x900] [--mp4] [--cursor] [--flow <file>] -- "<step>" …
#                                           records the steps running: normalized H.264 clip + contact sheet
#                                           + motion report + frames/ + events.json (each step in clip seconds,
#                                           with the box it clicked); --mp4 is a no-op, the clip is always mp4
#   vysu lang <persona> <lang>              language of the web app (localStorage VYSU_LANG_STORAGE_KEY), then reload
#   vysu sheet <name> [--cols N] [--max N] [--only "<glob>,…"] [--strip] [--open]   contact sheet(s) ≤ 1568 px
#                                           so they stay legible + index.html (six phone captures: one page);
#                                           --only: the captures a glob names, in that order (a .prev.png or a
#                                           -changed.png only when the glob spells it); --strip: one row at one
#                                           scale, a before / after pair → sheet-strip.png
#   vysu sheet <name> --compare [--against <name>]   before / after / zones triptych (compare.png) + slider page
#                                           (compare.html); a mobile capture with no baseline pairs with its .prev.png;
#                                           renders through the `render` session:
#                                           `vysu render <agent-browser args…>` to look at index.html / compare.html
#   vysu frame <name|file> [frame options…]   demo-ready export of a capture, a clip or a whole shots folder
#                                           (--preset pitch --title … --caption … for a 16:9 slide, --preset framed for
#                                            a device frame; a mobile clip from `mrec` and a web clip from `rec` both work)
#   vysu cut <take> --draft [--force]       a starting cut.json (montage script) from events.json + motion.txt:
#                                           what to keep, where to freeze, one empty chapter per shot — the agent
#                                           writes the text
#   vysu video <take> [--format landscape|portrait|all] [--check] [--draft] [--out <dir>]
#                                           renders cut.json with the Remotion toolkit into <take>/video/
#   vysu box <persona> <selector|@ref> [--page]   x,y,w,h of an element (1x px; --page: document coords for a --full
#                                           capture)
#   vysu mark <in.png> --out <out.png> [--box x,y,w,h[:label]]… [--grow 10] [--crop auto|x,y,w,h] [--pad N] [--dim]
#              [--zoom 2]
#   vysu check <persona> [--save <name>]    JS errors + failed API requests of the current session
#   vysu auth token <persona>               the persona's current API access token (for curl seeding)
#   vysu auth test <persona> [ios|android]  run the project's auth connector once and print each step that
#                                           held; web: a throwaway session of its own, closed at the end,
#                                           mobile: the real app (one install = one session)
#   vysu persona add|set|list [--json]|import <file> [--prefix <P>]   the project's personas, mode 600, never printed
#   vysu claim ios|android|<persona> [--minutes 20] [--note "<why>"]   keep a device / a session for a whole task,
#                                           and read back what the last agent left on it: state applied, screen, and
#                                           the one command that puts it back to the defaults. Each command of its
#                                           owner pushes the end --minutes further; a claim whose agent process is
#                                           gone is dropped
#   vysu claim ios --device "<simulator>" | vysu claim android --avd <name>   that device, which becomes this
#                                           owner's device: every next command drives it, no env var needed.
#                                           An owner holding two of a platform (the sub-agents of one session are
#                                           one owner) names the device on every command, VYSU_IOS_DEVICE /
#                                           VYSU_ANDROID_AVD: one that names none is refused, not guessed
#   vysu claim ios|android --any [--minutes 20] [--no-wait] [--note "<why>"]   a free device of the pool, made
#                                           this owner's device: a booted one, else a shut-down one it boots
#                                           (Android: under VYSU_ANDROID_MAX_RUNNING), else on iOS a clone
#                                           « <name> (vysu N) » of a shut-down one (VYSU_IOS_MAX_CLONES; `vysu release
#                                           ios --delete-clone` deletes it); pool = VYSU_IOS_DEVICES + the clones,
#                                           VYSU_ANDROID_AVDS. None free: waits VYSU_LOCK_WAIT listing who holds
#                                           what (--no-wait: exit 1 with that list)
#   vysu claim <persona> --any [--minutes 20] [--no-wait] [--note "<why>"]   a session of the persona nobody
#                                           uses, for a checker working next to another one as the same persona:
#                                           <persona>, else <persona>@2, @3… up to VYSU_WEB_SLOTS (4), each its own
#                                           browser. One that holds no login logs in (its own login, never a copy).
#                                           The `name it:` line names the session every command then uses
#                                           (vysu walk <persona>@2 …). None free: waits VYSU_LOCK_WAIT (--no-wait: exit 1)
#   vysu devices [--prune-clones [--dry-run]]   one line per simulator / emulator: booted, running or shut down,
#                                           free or claimed (by whom, until when), the command running on it, the
#                                           state applied; --prune-clones deletes the vysu clones nobody claims
#   vysu adb <args…>                        adb on this owner's emulator (-s <its serial>), under its lock
#   vysu simctl <verb> [args…]              xcrun simctl on this owner's simulator (its UDID after the verb), under
#                                           its lock; list / create / clone / runtime / help / pair run as they are
#   vysu release ios|android|<persona> [--force] [--reset] [--delete-clone]   hand it back (--force: someone else's claim;
#                                           --reset: defaults first — normal text, light, the default language)
#   vysu prune [--days 30] [--match "<glob>"…] [--dry-run]   drop the shots folders older than N days,
#                                           or the ones a glob names, whatever their age (--dry-run: just say which)
#   vysu cache clear                        forget what is remembered per device: simulator UDIDs, emulator
#                                           serials, scales, and the text size / appearance / language applied
#   vysu setup [--yes] [--dry-run] [--ios-device <n>] [--ios-old-device <n>] [--android-avds "<spec>;…"]
#              [--browser <path|default>]
#                                           machine-wide onboarding: tools, browser, simulators, emulators.
#                                           Every line is one of three things — fine (with the version),
#                                           optional and missing, required and missing — and it ends on the
#                                           counts and the exact commands to run (exit 1 on a required one).
#                                           With no terminal to answer, it reports and creates nothing;
#                                           --yes is how a script asks for the installing run.
#                                           --browser names an installed Chromium-based browser to drive
#                                           instead of the downloaded Chrome for Testing, `default` clears it
#   vysu init [--yes] [--skills-dir <dir>] [--agents-dir <dir>]   write .vysu/config in this project and install the
#                                           agent skills, and the visual-checker agent definition (Claude Code: .claude/agents)
#   vysu init --refresh-skills [--skills-dir <dir>] [--agents-dir <dir>]   re-copy this engine's skills (and the
#                                           visual-checker agent where one is installed), and nothing else
#   vysu doctor                             tooling, resolved config, connectors, personas, sessions, devices, locks
#   vysu checker [--for <agent family>]     how to delegate a visual check: the brief lives in the skill, the model the
#                                           checker sub-agent runs on is VYSU_CHECKER_MODELS for the calling agent tool
#   vysu update | vysu version              pull the engine, then the CHANGELOG since, the node tools it needs
#                                           and a reminder when this project's skills are older · the version,
#                                           the sha and the tools' versions
#
# `--no-color` (or NO_COLOR, or a stdout that is not a terminal) drops the markers' colours.
#   vysu <name> …                           an executable .vysu/commands/<name> of the project, with every VYSU_* exported
#   <persona>@N, wherever a persona goes       that persona's Nth browser session: its credentials, its own login and page
#                                           (`-@N` too: another anonymous browser, `vysu claim - --any`)
#
# Several agents share this Mac: every command locks the device or the persona session it drives,
# for its duration (another one waits VYSU_LOCK_WAIT seconds, 90 by default, then gives up). A claim
# holds one across several commands. The holder is $VYSU_OWNER, else the agent or terminal above.
# State: $VYSU_STATE (default ~/.vysu/<project>): personas.env (credentials, chmod 600), shots/, logs/.
# Browser state lives in ~/.agent-browser/sessions/ (managed by --restore).
